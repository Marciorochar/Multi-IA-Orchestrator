# PySide6 GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar uma interface desktop Windows em PySide6 para operar o núcleo atual do Multi-IA Orchestrator em modo fake, sem bloquear a janela e sem duplicar regras do engine.

**Architecture:** A GUI usa `MainWindow` na thread principal e um `OrchestratorWorker` movido para `QThread`. O worker chama o `Orchestrator` existente e converte eventos neutros do núcleo em sinais Qt. A CLI permanece funcional e as integrações reais continuam fora de escopo.

**Tech Stack:** Python 3.12+, PySide6 6.11+, asyncio, QThread/signals-slots, pytest, SQLite.

**Spec:** `docs/superpowers/specs/2026-11-23-pyside6-gui-design.md`

## Global Constraints

- Windows desktop; manter Python 3.12+ e compatibilidade com Python 3.14.
- PySide6 como dependência opcional `gui`; ambientes de núcleo não devem precisar de Qt.
- Modo fake explícito; nenhuma integração real com ChatGPT, Antigravity ou Codex nesta fase.
- GUI nunca executa o Orchestrator na thread principal.
- Stop é cooperativo e impede novas etapas.
- Pause acontece apenas em limites seguros entre estágios/ciclos.
- CLI atual `multi-ia` continua funcionando.
- Testes de GUI rodam com `QT_QPA_PLATFORM=offscreen`.
- Nenhuma credencial ou segredo em logs da GUI.

## Review Focus

1. Fechar a janela durante uma execução não pode deixar QThread ativa ou travar o processo.
2. Stop enquanto pausado deve cancelar em vez de ficar aguardando retomada.
3. Exceção no worker deve virar estado FAILED e restaurar controles, sem fechar a GUI.
4. Repositório inexistente ou objetivo vazio não pode iniciar execução.
5. Dois cliques rápidos em Iniciar não podem criar workers concorrentes.
